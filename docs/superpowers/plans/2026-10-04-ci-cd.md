# TrackBing CI/CD implementation plan

**Goal:** Reliable, reproducible pull-request checks and deliberately triggered,
commit-bound web/backend and native releases for the existing Expo/Supabase stack.

**Architecture:** A reusable, secret-free CI workflow runs parallel app, backend,
security, web/browser and native-export jobs, ending in one stable merge gate.
Manual release workflows first run that CI at the dispatched main commit; scoped
GitHub environments hold deployment credentials. Backend migrations/functions
precede the web release. Native signed builds are separate and never auto-submit.

**Threat model:** PR code and dependencies are untrusted; forks must receive no
deployment secrets. A wrong environment, stale commit, unchecked artifact or
out-of-order migration could expose private health data or break clients. Pin
actions, restrict tokens, serialize releases, validate configuration and separate
secret-free verification from credential-bearing release jobs.

**Decisions:** Node 24 LTS; exact action SHAs and tool versions; npm lockfile
installs; controlled paid-API/browser fixtures; no production execution here.
Add only dev-only Playwright (portable browser checks) and YAML (workflow-policy
validation). Retain known dependency issues as explicit, short-lived advisory
exceptions, blocking every unlisted high/critical issue; never claim the audit is
clean. Keep mandatory checks on every PR, main push and merge-queue event.
